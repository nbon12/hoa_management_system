## How to run a slice (the proven workflow)

Slices are Spec Kit features. For each remaining slice, on **its own feature branch off `main`**
(the branch already exists per the table; if starting fresh, `git checkout main && git pull`,
then check out the slice branch):

1. `/speckit.clarify` — resolve ambiguities into the spec's `## Clarifications` (≤5 questions;
   the skill recommends an option per question — "recommended" answers were fine for A/D).
2. `/speckit.plan` — generates research.md, data-model.md, contracts/, quickstart.md; runs the
   agent-context script (use arg `claude`, **not** `claude-code` — the script rejects the latter).
3. `/speckit.tasks` — dependency-ordered `tasks.md`, test-first (constitution mandates red→green).
4. `/speckit.analyze` — read-only cross-artifact consistency check; fold remediations into tasks.
5. `/speckit.implement` — execute phase by phase, mark tasks `[X]`, commit per logical unit.

**Repo is squash-merge only.** Commit trailer convention (from CLAUDE.md / session):
```
Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
Claude-Session: https://claude.ai/code/session_01PFu6bCnvmB5ZeYZWST5JB8
```
PR bodies end with the `🤖 Generated with [Claude Code]` block.

**Merged branches are immutable** (CLAUDE.md rule) — never commit to a branch after its PR
merges; branch off `main` for follow-ups (that's why the D deploy-smoke fix became #120 on a
new `023-` branch).

## Hard-won gotchas (these will save hours)

1. **Cookie auth is not domain-portable** (020-D). See memory
   `cookie-auth-breaks-dev-smoke-candidate-model` and `specs/020-.../contracts/auth-session.md`.
   The deploy-dev smoke now does a **two-build split** (candidate origin for smoke, stable
   `api-dev.nekohoa.com` for the promoted artifact). Any change touching that gate must preserve it.
2. **Rate limiting bites e2e**: direct `*.run.app` traffic bypasses Cloudflare, so it has no
   trusted-edge header and lands in the strict shared **`unknown`** partition (30/min base). Dev
   raises auth **and** unknown buckets to 300/min (`appsettings.Dev.json`); Development mirrors it
   for local suites. If a slice adds auth-adjacent endpoints under test, watch for 429s.
3. **Enforcing CSP breaks Angular critical-CSS inlining** — the optimizer emits
   `<link media="print" onload="…">` whose inline `onload` the CSP blocks (half-styled app).
   `inlineCritical` is disabled in `angular.json`. Don't re-enable it.
4. **Fresh-DB seeding**: `AuthSeeder` (017-A) pre-creates SAKURA-003; `PropertySeeder` skips
   existing account numbers (`SeedNeighborsAsync`). New seed data must stay idempotent or fresh
   Neon branches (pr-env) fail on `IX_Properties_AccountNumber`.
5. **Local test pollution**: an untracked `HOAManagementCompany/appsettings.Secrets.json`
   (gitignored) can complete partial SendGrid/Twilio configs and change local test outcomes.
   `StartupValidationTests.ValidBaseline()` is hermetic against it; new config tests should be too.
6. **Playwright auth**: shared `storageState` snapshots are gone (strict refresh rotation makes
   them impossible). Each test does its own API login via `e2e/helpers/auth.ts::establishSession`.
7. Agent-context script arg is `claude`. `update-agent-context.sh claude-code` errors.
